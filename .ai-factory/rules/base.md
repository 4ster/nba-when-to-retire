# Базовые правила проекта

> Конвенции, выведенные из анализа спецификации (`SPEC.md`) и аксиом (`RULES.md`).
> Это «как писать код»; «что обязательно/запрещено» — в `RULES.md` (enforceable-гейт).
> Правьте по мере роста кодовой базы.

## Структура проекта

Проект двухфазный (см. `SPEC.md` §6, `PROMPT.md`):

- `pipeline/` — офлайн-пайплайн данных на Python (build-time). Скачивание датасета,
  агрегация, выгрузка слим-JSON. Браузер этот код не исполняет.
- `pipeline/tests/` — тесты пайплайна (pytest). Пишутся **раньше** реализации (TDD).
- `index.html` — единственный артефакт рантайма: self-contained, инлайн-данные,
  один JS-блок. Открывается двойным кликом.
- `SPEC.md` / `RULES.md` / `PROMPT.md` — источники истины (код порождается из них).

## Именование

- **Python**: модули и функции — `snake_case`, классы — `PascalCase`,
  константы — `UPPER_SNAKE_CASE`.
- **Ключи данных** (контракт `SPEC.md` §2): `snake_case`, метрики сохраняют
  доменный регистр (`PTS_36`, `TS_pct`, `FG3_pct`, `BPM`).
- **CSS-переменные тем**: `--prefix-role` (семантические токены, не цвета-литералы).
- **JS**: переменные/функции — `camelCase`; никаких сокращений в ущерб ясности.

## Обработка ошибок

- **Python**: пропуски значений обрабатываются явно, без «тихого» отбрасывания строк;
  валидация качества данных до и после трансформаций; падать с понятным сообщением,
  а не молча искажать агрегат.
- **JS**: `JSON.parse(#seed-data)` строго в `try/catch` на `DOMContentLoaded`;
  при сбое — деградация с явным сообщением, не пустой экран.

## Логирование

- **Python**: логировать ключевые шаги пайплайна (размер выборки, число игроков
  после фильтра минут, итоговый размер JSON) и контроль бюджета < 300 КБ.
  Уровень — через переменную окружения, не хардкодом.
- **JS**: рантайм-лог минимален; ошибки парсинга/рендера — в консоль с контекстом.

## Тесты

- Инструмент: **pytest**. Покрыть до фронта: корректность дельта-метода,
  нормализацию per-36/per-100, контроль survivorship bias, соответствие схеме
  контракта §2 и бюджет размера JSON.
- Фронт не начинаем, пока тесты пайплайна не зелёные (`RULES.md` → Процесс).

## Сборка и валидация

- После каждой сборки `index.html`: `node --check` по извлечённому JS-блоку;
  strip null-байтов; CDN-ссылки с зафиксированными версиями (без `@latest`).
- Данные — как `<script id="seed-data" type="application/json">`; стартовый
  `data-theme` на `<html>`.
