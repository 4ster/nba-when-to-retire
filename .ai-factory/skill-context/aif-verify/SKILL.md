### Render-verify the single-file HTML in a real DOM, not just syntax
**Source**: 2026-06-07-12.40.md, codebase (`tools/verify_dom.mjs`)
**Rule**: For `index.html` (single-file d3 scrollytelling), verification MUST include a
headless render (Playwright Chromium, or jsdom with d3 injected — see `tools/verify_dom.mjs`,
`task verify`) that executes the app on real embedded data and exercises every scene
(US-1…US-7), the theme toggle, and the sandbox. `node --check`/`check_html.mjs` validate
syntax only — they miss hoisting and runtime errors (e.g. `renderScene(undefined)`, `MARGIN`
used before assignment) that a real DOM catches. Assert zero console errors (a broken CDN/SRI
load surfaces here too).
Also exercise any **modal/overlay dialog** (e.g. the "?" methodology modal): open it via its
trigger and assert focus moves into the dialog, Esc **and** backdrop-click close it, focus
returns to the trigger, and `role="dialog"`/`aria-modal="true"` are present — focus-trap and
focus-return logic are invisible to syntax checks.
