## Rules

### External-data robustness (no crash on dirty input)
**Source**: 2026-06-07-12.40.md, 2026-06-07-13.15.md, codebase (`position_group`, `notable._native_id`)
**Rule**: Parsers/normalizers of external datasets (e.g. `pipeline/fetch.py`,
`pipeline/datasets.py`, `pipeline/transform/normalize.py`) MUST tolerate dirty real-world
values — combined/abbreviated codes (e.g. position `G-F`, `PG-SG`), empty strings, `None`,
and missing fields. Normalize first (e.g. take the primary token), then fall back to a sane
default with `log.warning(...)`. NEVER raise on a single unrecognized record — one bad row
must not crash the whole build.
Guard **wrong-TYPE** values, not just dirty strings: a float `NaN` is **truthy**, so
`(pos or "").strip()` still passes NaN through and raises `AttributeError` — check
`isinstance(x, str)` before string ops instead of relying on `x or default`. Likewise do NOT
assume `player_id` is an integer: some datasets ship a **native string** id, so coerce only
numpy/pandas ints for JSON (`int(pid)`) and keep strings as-is.

### Derive data-recency labels from the data, never hardcode
**Source**: codebase (`build.season_label`, `meta.season_min/season_max`); RULES «данные по сезон 20XX–XX»
**Rule**: For the data-date UI requirement and any season-range display, compute the label
and `season_min`/`season_max` from the built dataset into `meta` (in `pipeline.build`), and
remove hardcoded dates from `Taskfile.yml`/CLI. A hardcoded label silently goes stale and
misreads as "single season" even when the dataset spans decades (the exact bug that prompted
the dataset-refresh feature).

### NaN-safety in pandas aggregations
**Source**: 2026-06-07-12.40.md, 2026-06-07-13.15.md
**Rule**: Guard pandas reductions that throw on all-NA groups — `idxmax`/`argmax`/`std`
raise `ValueError: Encountered all NA values`. Drop NA rows before such ops (e.g.
`df[df["value"].notna()]`) or guard explicitly. Eliminate NaN at the source
(e.g. `se = (sd/sqrt(n)).fillna(0.0)`) instead of masking it downstream with `np.where`.

### Account for dataset censoring in age/duration metrics
**Source**: 2026-06-07-13.15.md
**Rule**: For metrics like "age of peak", "career length", or "early fade", exclude
observations censored by the dataset boundary — players whose last season equals the
dataset's max season are still active, not faded; including them produces false conclusions.

### Single inline JS: initialize at the end of the IIFE
**Source**: 2026-06-07-12.40.md
**Rule**: In `index.html`'s single `<script id="app">` IIFE, call init functions
(`initMeta/initTheme/initScrolly/initSandbox`) ONLY after all `var` constants and function
declarations. `var` initializers are not hoisted — calling init earlier runs scene code
before `currentScene`/`MARGIN`/etc. are assigned (silent runtime crash).

### Theme-aware charts need a re-render hook
**Source**: 2026-06-07-12.40.md
**Rule**: Every chart that reads CSS theme tokens (`cssVar(...)`) must expose a re-render
hook that the theme toggle invokes, so switching theme recolors ALL charts (including the
sandbox), not just the active scrolly scene. Verify with a headless click in jsdom/Playwright.
