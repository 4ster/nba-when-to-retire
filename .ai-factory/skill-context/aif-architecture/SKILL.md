## Rules

### Per-dataset adapter, not a global column_map
**Source**: 2026-06-07-13.15.md, codebase (`load_drgilermo`, `load_sumitrodatta`)
**Rule**: Integrating an external dataset into the §2 contract requires more than column
renaming — derived fields must be synthesized (e.g. `active_next` from presence in the next
season), and source quirks handled. Put this in a dedicated, unit-testable per-dataset adapter
module (`pipeline/datasets.py`, registered in `DATASET_LOADERS`, selected via `build --dataset`),
not in a generic `column_map`. Keep `fetch.load_raw` for already-conformant CSVs only.
An adapter's input may be a **directory**, not a single CSV, and it may need to **JOIN
multiple source files** from one dataset (e.g. sumitrodatta joins `Advanced.csv` for
`bpm`/`ts_percent` with `Player Totals.csv` for `pts/trb/...` on key `(season, player_id)`).
Synthesize `player_id` **only when the source lacks one** — prefer a native id column when
present (drgilermo → `factorize` from name; sumitrodatta → native string id, no factorize).
The traded-player dedup marker is **source-specific** — encode it per adapter
(`TOT` in drgilermo, `2TM`/`3TM`/… in sumitrodatta).
