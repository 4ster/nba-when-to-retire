# Интеграция реальных данных (drgilermo): адаптер, NaN-устойчивость, цензурирование

**Date:** 2026-06-07 13:15
**Files:** pipeline/datasets.py, pipeline/build.py, pipeline/transform/notable.py, pipeline/transform/skill_decline.py, pipeline/requirements.txt, Taskfile.yml, index.html
**Severity:** high

## Problem

Перевод пайплайна с синтетического seed на реальный Kaggle-датасет
`drgilermo/nba-players-stats` (`Seasons_Stats.csv`) вскрыл несколько проблем,
невидимых на «чистой» синтетике:

1. Датасет не содержит полей контракта §2: нет `player_id` (игроки по имени),
   нет `active_next`; обменянные за сезон игроки дублируются (строки `TOT` + по командам).
2. **Crash:** `notable._career_stats` падал с `ValueError: Encountered all NA values`
   на игроках, у которых весь `value` (BPM) = NaN (карьеры до эпохи BPM, < 1974).
3. **Честность нарратива:** в `early_fade` попадали ещё активные звёзды (Кайри Ирвинг,
   Андре Дрэммонд) — артефакт правого цензурирования (данные обрываются на 2017).
4. `skill_decline` давал `null`-точки `value_pct` для STL/BLK до 1974 (рвут линию).

## Root Cause

- **Допущения о форме данных, проверенные только на синтетике.** Адаптация к источнику
  (id, active_next, дедуп) и «грязные» реальные значения (NaN BPM/STL до 1974,
  обрезанные карьеры) не были предусмотрены, потому что тестовые данные были идеальны.
- `idxmax`/`argmax` в pandas бросает на полностью-NaN серии.
- Метрика «молодой пик» в `early_fade` неявно предполагала полные карьеры; для снимка
  с фиксированной датой это ложно для ещё активных игроков.

## Solution

- `pipeline/datasets.py`: адаптер `load_drgilermo` — дедуп `TOT`, `player_id` через
  `factorize(name)`, `active_next` по присутствию `(player_id, season+1)`, `value`=BPM;
  реестр `DATASET_LOADERS`, флаг `--dataset` в `build`.
- `notable`: отбрасывать строки с `value`=NaN до расчётов (без них idxmax безопасен);
  исключать right-censored (последний сезон = max сезону данных) из `early_fade`.
- `skill_decline`: `dropna(subset=["value_pct"])` — без null-точек во фронте.
- pandas поднят до 3.x; добавлены тесты (адаптер, all-NaN, цензурирование).

Результат честен: пик ценности ≈ 25–26, долгожители Robert Parish / Jason Kidd,
рано угасшие Andrew Bynum / Darius Miles; слим-JSON 36 КБ < бюджета; 62 теста зелёные.

## Prevention

- **Тестировать парсеры внешних данных на «грязных» кейсах:** отсутствующие поля,
  NaN-серии, дубли (обмен), частичное покрытие метрик по годам.
- **Защищать агрегаты от полностью-NaN групп** (idxmax/argmax/std) и устранять NaN
  в источнике, а не маскировать.
- **Учитывать цензурирование данных** в любых метриках «возраст пика / длительность» —
  исключать наблюдения, обрезанные границей датасета.
- **Адаптер на датасет, а не глобальный column_map** — синтез производных полей
  (id, active_next) живёт в одном месте и тестируется.
