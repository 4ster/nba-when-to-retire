# Spec: дашборд «Игроки NBA: когда пора на пенсию?»

Single-file HTML scrollytelling о возрастных кривых игроков NBA.
Этот документ — **источник истины**. Код порождается из него, не наоборот.

---

## 0. Конституция (non-negotiable)

1. **Один self-contained HTML-файл.** Открывается двойным кликом, без сборки и сервера. Данные встроены инлайн.
2. **Скроллителлинг, не BI-дашборд.** Вертикальный нарратив со sticky-графикой и сменой сцен. Архитектура «KPI-сетка / один экран без прокрутки» из BI-методики **сознательно НЕ применяется**.
3. **Честность данных.** Кривая старения строится **дельта-методом** (год-к-году по одному игроку), на **скоростных метриках** (на 36 мин / на 100 владений), с контролем survivorship bias. Внеигровые данные (зарплаты, реклама, мотивация) не используются — методическая оговорка показывается аннотацией.
4. **Ремесло (из скила insba §5/§7/§8/§21) = критерии приёмки:** минимум не-данных (убраны оси/сетка/рамки, прямые подписи), единицы — в заголовках, ≤2 шрифтов, цвет theme-aware и семантический. Сборка: один JS-блок, `node --check` после каждой сборки, strip null-байтов, seed-данные как `<script type="application/json">`, версии CDN зафиксированы.
5. **Язык интерфейса — русский.**
6. **Производительность.** Только предагрегированные данные; Canvas/SVG; плавный скролл; уважать `prefers-reduced-motion`.

---

## 1. Намерение

**Цель одной фразой:** показать, в каком возрасте игрок NBA выходит на пик и когда «пора на пенсию», и что спад зависит от амплуа, навыка и эпохи.

**Аудитория:** широкая — болельщики и аналитики; читается без знания статистики.

**Вывод за 10 секунд:** пик ≈ 26–28 лет, дальше спад; большие сваливаются раньше защитников; современные карьеры длиннее.

---

## 2. Контракт данных

**Атом:** игрок-сезон (`player-season`).
```
{ player_id, name, age, season, era_bucket, position_group,
  minutes, games,
  PTS_36, REB_36, AST_36, STL_36, BLK_36, TS_pct, FG3_pct,
  value,            // одна метрика ценности: BPM | WS/48 | VORP (выбрать в §7)
  active_next }     // активен ли в следующем сезоне (для survival)
```

**Источник:** Kaggle `eoinamoore/historical-nba-data-and-player-box-scores` (биография + бокс-скоры с 1947, продвинутые) и/или `drgilermo/nba-players-stats` (3000+ игроков, 60+ сезонов). Продвинутые метрики при необходимости — через `nba_api` / basketball-reference.

**Агрегация (предвычислить, в файл кладём ТОЛЬКО производное):**
- `aging_curve`: для каждого `(age × position_group × era_bucket × metric)` — среднее по дельта-методу + доверительный коридор + `n`.
- `survival`: доля игроков, ещё активных, по возрасту.
- `skill_decline`: нормированные к пику (=100%) кривые по компонентам навыка.
- `notable`: 10–20 выбранных карьер (долгожители / раннее угасание) как индивидуальные ряды.

**Бюджет размера:** производный JSON < ~300 КБ, инлайн.

**Методические заметки:** дельта-метод против survivorship bias; per-36/per-100 нейтрализует load management; разрез по эпохам показывает уплощение кривой.

## 3. Сцены (user stories + критерии приёмки)

Каждая сцена = sticky-графика + скроллящийся текст + одно аналитическое утверждение.

**US-1. Средняя кривая.** Как болельщик, я вижу единую кривую «ценность × возраст» и сразу понимаю возраст пика и форму спада.
- AC: кривая `value` от `age`; пик подписан аннотацией; виден коридор неопределённости; тонкая ось времени, значения на ключевых точках.

**US-2. По амплуа.** Я сравниваю защитников / вингов / больших и вижу, кто сваливается раньше.
- AC: 3 кривые, цвет = амплуа (семантика), точка дивергенции подписана; прямые подписи вместо блока-легенды.

**US-3. Что умирает первым.** Я вижу порядок угасания навыков: атлетизм/подбор/защита раньше, чем бросок/штрафные/пас.
- AC: small multiples или «лесенка» по компонентам, нормировано к пику=100%, порядок подписан.

**US-4. Эпохи.** Я вижу, что современные кривые длиннее и выше в хвосте (спортивная медицина).
- AC: кривые по эпохам наложены; современный хвост выделен цветовым акцентом; аннотация «почему».

**US-5. Выбросы.** Я вижу долгожителей против рано сгоревших на фоне средней.
- AC: средняя полоса + 2–3 именованные индивидуальные траектории; контраст акцентом.

**US-6. Обрыв.** Я вижу, что спад бывает плавным и резким, и когда игроки уходят из лиги.
- AC: распределение возраста ухода / скорости спада; медиана подписана.

**US-7. Песочница (финал).** Я кручу фильтры (амплуа / эпоха / метрика) и кривая пересобирается.
- AC: фильтры пересчитывают все видимые кривые; базовая средняя остаётся для сравнения; есть сброс.

---

## 4. Интеракции

- Скролл двигает смену сцен (sticky-графика).
- Hover по точке → тултип (возраст, значение, `n`).
- Песочница: селекты/тоглы (амплуа, эпоха, метрика).
- Переключатель темы (светлая/тёмная), закреплён.
- `prefers-reduced-motion` отключает анимации.

---

## 5. Non-goals

- НЕ BI-дашборд с KPI-сеткой.
- НЕ реальное время — статический снимок с проставленной датой данных («данные по сезон 20XX–XX»).
- Без рантайм-загрузки данных в браузере (CORS/ToS источников, размер сырья, рассинхрон цифр с авторскими выводами). Обновление = осознанная пересборка офлайн-пайплайном с ревью нарратива и бампом версии.
- Без зарплат / рекламы / мотивации.
- Без шот-чартов.
- НЕ полноценный стат-эксплорер — только нарратив про старение.
- Без зависимостей от localStorage, кроме опционального сохранения сценария песочницы.

---

## 6. Технологии и сборка

- `d3` (шкалы, кривые) + `scrollama` или IntersectionObserver для скролл-триггеров; Canvas, если точек много.
- Один файл: `index.html` + инлайновый `<script id="seed-data" type="application/json">`; один JS-блок; CDN с версиями; `node --check` после сборки.
- Гейт приёмки: чек-листы §5/§7/§8/§21 скила пройдены.

---

## 7. Открытые вопросы (решить до/в фазе plan)

1. Метрика ценности: `BPM` vs `WS/48` vs `VORP` — выбрать одну.
2. Границы эпох (например ≤1989 / 1990–2009 / 2010+).
3. Минимальный порог минут/сезонов для включения игрока (фильтр шума).
